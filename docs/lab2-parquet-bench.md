# ЛР2: дополнительное задание — кодеки Parquet и row groups

## Что сравнивалось

- Данные: `parquet.events` ЛР2, 3 суток — 2026-10-23…25, **2 827 716 строк**.
- Каждый вариант записан **одним файлом без партиций**, чтобы `ROW_GROUP_SIZE`
  был именно заданным, а не зависел от размера партиции.
- Кодеки: `UNCOMPRESSED`, `SNAPPY`, `GZIP`, `ZSTD`.
- Размеры row group: 100 000, 500 000, 1 000 000 строк.
- Запрос: число событий по часам и странам; три запуска, медиана, время в мс.
- Размер: `stat` по файлу; row groups: `parquet_file_metadata`.
- Детализация групп: `parquet_metadata`.

Измерения выполнены на стенде (DuckDB 1.5.5, 2 потока, лимит памяти 2 ГБ).
Скрипт `jobs/parquet_bench.py` повторяет замер.

## Вывод

Для clean-слоя ЛР3 выбран **ZSTD + ROW_GROUP_SIZE = 500 000**.

Почему:

- самый маленький размер — **57,5 MiB** (у gzip 57,7, у snappy 89,0, у
  uncompressed 199,6);
- запись **2,22 с** против **6,14 с** у gzip — в озере это заметно;
- запрос **43,0 мс** против 33,8–36,3 мс у быстрых вариантов: разница небольшая,
  а размер в 1,6–3,5 раза меньше;
- 100 000 даёт 29 row groups и 59,2 MiB, то есть больше метаданных при
  сопоставимой скорости; 1 000 000 даёт 3 группы и заметно медленнее (48,7 мс);
- 500 000 — компромисс: 6 групп, минимальный размер, стабильное время.

В `jobs/clean.sql` ЛР3 это записывается так:

```sql
COPY (...) TO 's3://lake/clean/events'
(FORMAT PARQUET, COMPRESSION ZSTD, ROW_GROUP_SIZE 500000,
 PARTITION_BY (event_date), OVERWRITE_OR_IGNORE true);
```

## Как повторить на стенде

1. Скопировать `jobs/parquet_bench.py` в `~/stand/jobs/`.
2. Установить DuckDB в виртуальное окружение стенда:

```bash
cd ~/stand
.venv/bin/pip install duckdb==1.5.5
```

3. Запустить:

```bash
.venv/bin/python jobs/parquet_bench.py
```

По умолчанию читается `data/duckdb/parquet/events` и пишется
`data/duckdb/bench`; результаты — в `data/duckdb/bench/results.md`.

Период можно переопределить через переменные окружения:

```bash
FROM_DATE=2026-10-23 TO_DATE=2026-10-25 .venv/bin/python jobs/parquet_bench.py
```

Предусловие: выполнен `jobs/to_parquet.sql` ЛР2.

## Ограничения

- Запрос — агрегат без предиката по времени; на S3/с реальными фильтрами
  преимущество маленьких row groups может быть заметнее.
- Замеры на стенде, DuckDB 1.5.5; числа при повторном запуске могут немного
  отличаться, но соотношение кодеков и размеров сохраняется.
- Запись измерена внутри Python-процесса DuckDB, без запуска контейнера.
