# Паспорт источника: sensor.community

## Доступ

- Поток: опрос раз в 5 минут, по одному запросу на страну из `SOURCE_FILTER`. Адрес задаётся `COLLECTOR_COUNTRY_URL`, для варианта это `https://data.sensor.community/airrohr/v1/filter/country={country}`.
- Весь поток для замера до фильтра: `COLLECTOR_GLOBAL_URL`, `https://data.sensor.community/static/v2/data.json`. В слой он не пишется.
- История: CSV по датчику и суткам, `COLLECTOR_ARCHIVE_URL`. Для варианта это `https://archive.sensor.community/{date}/{date}_{slug}_sensor_{sensor_id}{suffix}.csv`. `{suffix}` пустой или `_indoor`.
- Глубина архива: с 2015 года. Файл суток появляется на следующие сутки.
- Схема истории: те же события, ключ `sensor_id` и `timestamp`. Пропуск в записи закрывается архивом тех датчиков, которые поток отдал для стран задания. В CSV нет страны, высоты, признака помещения, пина и id замера. Страна подставляется из снимка потока.

## Лицензия и условия использования

- ODbL 1.0. При публичном использовании указывается источник sensor.community, производные базы — под той же лицензией.
- В этой работе данные остаются на стенде и не публикуются.

## Лимиты и представление клиента

- Лимиты не объявлены. Данные обновляются раз в 5 минут, опрос не чаще.
- Заголовок `User-Agent` — переменная `COLLECTOR_USER_AGENT`: имя программы и адрес почты.
- Ответы 429 и 5xx, а также обрыв сети, повторяются с паузой 1, 2, 4, … секунд, не больше пяти попыток за опрос.

## Схема события

| Поле | Тип | Смысл | Пример |
|---|---|---|---|
| event_key | string | `sensor_id` и `event_time` | `55469\|2026-10-10T21:40:02.000Z` |
| event_time | string | время замера, UTC, ISO-8601 с миллисекундами | `2026-10-10T21:40:02.000Z` |
| received_at | string | время получения сборщиком, UTC | `2026-10-10T21:51:00.670Z` |
| source | string | значение оси `SOURCE` | `sensors` |
| measurement_id | integer или null | id замера в потоке; в архиве поля нет | `30991926434` |
| sensor_id | integer | id датчика | `55469` |
| sensor_type | string | тип датчика | `SDS011` |
| pin | string или null | пин на плате; в архиве нет | `1` |
| location_id | integer | id места установки | `41334` |
| latitude | string | широта, как отдал источник | `47.872` |
| longitude | string | долгота, как отдал источник | `16.384` |
| altitude | string или null | высота, метры; в архиве нет | `228.2` |
| country | string | код страны | `AT` |
| indoor | integer или null | `1` — датчик в помещении; в архиве нет | `0` |
| values | object | тип величины → значение строкой | `{"P1":"0.50","P2":"0.35"}` |

- Ключ события: `sensor_id` и `timestamp`. Id замера в архиве отсутствует, поэтому ключом он быть не может. Пара уникальна для одного замера; повтор соседнего окна имеет тот же ключ.
- Время события: поле `timestamp`, часовой пояс UTC, точность источника — секунды. В событии пишется `.000Z`.

## Фильтр потока и объёмы

- Фильтр задания: `PL,CZ,AT`.
- Интервал наблюдения: 2026-10-23T00:01:15Z — 2026-10-23T23:56:35Z, сутки потока в `data/raw/stream/dt=2026-10-23`. В каталоге все 24 часа, 786 файлов, 262 опроса. Опросов меньше 288, потому что цикл — это сам запрос и пауза 5 минут после него.

| | До фильтра | После фильтра |
|---|---|---|
| событий в минуту | 3524 | 670 |
| байт в сутки до сжатия | 2 043 747 210, оценка | 387 524 865 |
| байт в сутки после сжатия | 212 171 660, оценка | 40 230 902 |

До фильтра — четыре снимка `data.json` за эти сутки (`msg=sample` в журнале): в среднем 17 620,75 события на окно, из них 1 871 в PL, CZ, AT. Деление на 5 минут даёт 3524 и 374 события в минуту. Это один текущий замер на датчик. Ответ в слой не пишется. Байты до фильтра — оценка: 3524 события в минуту на 1440 минут, средняя длина записанной строки этих суток 403 байта, сжатие файла этих суток в 9,63 раза.

После фильтра — строки файлов этих суток: 962 253 события, без сжатия 387 524 865 байт, gzip 40 230 902 байт. На минуту интервала (1 435,3 мин) — 670 событий. Журнал за те же сутки сходится с файлами: `new` = 962 253. Со страновых адресов пришло `kept` = 990 192 (690 в минуту); 27 939 повторов ключа отброшены. Страны в файлах только PL, CZ и AT: 645 136, 100 852 и 216 265. Страновой адрес отдаёт все замеры пяти минут, часто два на датчик, поэтому записанный поток больше, чем 374 в минуту у `data.json`.

- Восемь недель после фильтра и сжатия: 40 230 902 × 56 = 2 252 930 512 байт, это 2,10 ГиБ потока. Одни сутки истории 2026-10-21 — 16 537 680 байт gzip, 0,02 ГиБ. Вместе 2,11 ГиБ при пределе 20 ГиБ.
- Ограничение, которое наступит первым при росте потока: диск, предел `COLLECTOR_RAW_LIMIT_GB`. Запас до 20 ГиБ — рост потока примерно в девять с половиной раз. Память службы 512 МБ при текущем ответе страны (тысячи замеров) кончится на два порядка позже, сеть на несколько мегабайт за опрос не загружена.

## Известные дефекты

- Окна соседних опросов перекрываются. Повтор отбрасывается по ключу. За сутки 2026-10-23 из 990 192 событий фильтра журнал отбросил 27 939 повторов (2,8 %) и записал 962 253.
- За те же сутки 4 507 пар «датчик — время» пришли с разными `values` (0,46 % от 990 192). В слой остаётся первая копия.
- Значения источник отдаёт строками. В архиве встречается текст `unavailable`, например у счётчика импульсов.
- Часть датчиков стоит в помещении, координаты у части датчиков заведомо грубые. Это не исправляется в сыром слое.
- Имя типа в архиве может отличаться от API: API `Radiation SBM-20`, колонка CSV `Radiation_SBM-20`, файл `radiation_sbm-20` и для помещения суффикс `_indoor`.
- Архив не содержит страну. В историю попадают только датчики, которые были в окне потока в момент загрузки. Датчик без файла за эти сутки пропускается.
